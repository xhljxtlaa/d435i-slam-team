# 当前深度相机 + IMU 模式

## 点大小、显示负载和失效恢复

- RViz 点云使用 2 像素 Points，替代 2.5 cm Flat Squares，关闭点云选择功能；
  RViz 最大帧率 15 FPS。
- 显示轨迹最多 3000 个采样位姿，最多 5 Hz 发布，RViz Buffer Length=1；
  /odometry 和 CSV 位姿记录保持原更新频率。历史轨迹不再无限增长。
- 检测连续三帧可用长轨迹特征不足 6 个、非有限状态、相邻帧位移超过 2 m，
  或显著异常的 IMU 偏置时，释放处理锁后重置估计器，避免递归锁造成卡死。
- 重置发布 /vins_estimator_reset，清空 RViz 轨迹和累积地图，之后从新原点初始化；
  这是失效后的恢复策略，不是回环重定位或跨失效保图。重置也不替代标定。
- 保留相机模型，避免每次恢复重复加载追加模型。
- 测试：tracking_health_test 验证各类失效检测；隔离 ROS_DOMAIN_ID=73 的
  recovery_integration.py 验证有纹理→空白→纹理返回，轨迹生成、重置通知、
  空轨迹及恢复后输出均通过。测试不会向实际相机所在 ROS 域发送合成数据。

## 最新噪声与运动更新调整

- 相机开启 enable_sync，关闭未被估计器使用的真实右红外流。
- 深度启用 SDK 空间保边滤波：magnitude=2、alpha=0.5、delta=20、holes_fill=0。
  时间滤波和独立孔洞填充关闭。当前驱动启用 disparity_filter 后出现
  DISPARITY32 无法发布的错误，已禁用该项并验证恢复正常深度输出。
- 深度模式处理每个配对输入帧，取消原先隔帧处理；每帧用度量深度路标的
  PnP RANSAC 加内点精化初始化位姿，再保留 IMU 因子参与联合优化。
- 40 秒运动检查：轨迹姿态数 369→917、累积地图 75→896 点；
  画面有明显运动，位姿范围约 0.32 / 0.28 / 0.08 m，证实该段未冻结。
- 之后静置采样，近景有效像素时间标准差的中位数约 0.89 mm。
  修改前采样为 1.35 mm，但中间场景和视角发生变化，不作为严格同场景降噪比。
- 当前测量采用下限由 0.25 m 调整为 0.18 m，depth_imu.yaml 为准；
  累积地图距离范围为 0.18–8 m。官方数据表列出 640×480 时 D435i min-Z
  约 175 mm；低于软件下限的测量不用于估计。
- RViz 的 Depth Image 改为 /camera/depth_preview：固定 0.18–1.0 m TURBO 色标，
  带米制图例；黑色为无测距，白色为低于显示下限，灰色为超过上限。
  这是独立可视化，彩色图不输入估计器；不增加硬件测距精度。

## 数据路径

- 左红外图：`/camera/camera/infra1/image_rect_raw`，640×480。
- 相机深度图：`/camera/camera/depth/image_rect_raw`，16UC1，原始单位 1 mm。
- IMU：`/camera/camera/imu`，约 200 Hz，开启参与优化。
- 配对深度和左红外时间戳误差不超过 3 ms；订阅端队列有界。
- 已实测两幅图像的驱动内参、尺寸和光学坐标系一致，可直接按像素取深度。

在左红外图跟踪特征，从相机深度图的 3×3 邻域读取米制 Z 深度，剔除零值、
非有限值、深度突变边缘及 0.25–6 m 以外的观测。只用有效相机测距创建新路标，
新路标直接用测量值初始化；测不到深度时不回退到图像三角化初始化。

为了复用 VINS 已有的优化与边缘化，将测量深度投影为一个虚拟右目观测。
这个观测由测距生成，不来自右图匹配。一般双目外参下：
`p1 = R1^T * (R0 * (ray0 * depth) + t0 - t1)`。
现有左右重投影残差因此成为相机测距的等价约束，并与时间序列视觉残差、
IMU 预积分、速度/偏置和历史先验共同优化。优化后的路标深度可以偏离测量值，
并非对原始深度图进行逐点原样显示。

此模式固定相机外参及零时间偏移；读取配置时会拒绝同时开启外参/时间偏移
在线估计，避免生成观测的固定几何与优化变量不一致。
仍保留两个相机模型供虚拟观测使用；实际右红外图不用于测距。

## 启动

分别在两个终端运行：
```bash
source /opt/ros/humble/setup.bash
ros2 launch realsense2_camera rs_launch.py config_file:=/home/he/vins_ws/config/d435i/camera.yaml
```
```bash
source /opt/ros/humble/setup.bash
source /home/he/vins_ws/install/setup.bash
ros2 run vins vins_node /home/he/vins_ws/config/d435i/depth_imu.yaml
```

累积地图节点和 RViz 用此前的入口运行。切换估计器前应清空旧地图。

## 验证及限制

- 已通过单元测试：米制采样、空洞/边缘/范围过滤、数据类型检查，多个深度
  在带旋转/平移外参下生成观测并恢复原深度，误差小于 1e-8 m。
- colcon 编译通过；运行日志确认 USE_IMU: 1 及实测深度来源。
- 30 秒检查：5998 条 IMU、482 帧深度、255 条位姿，典型每帧约 60 个有效
  深度观测；画面基本静止，三轴位姿跨度约 4.3 / 4.4 / 5.9 mm。
- 随后的 60 秒检查：482 条位姿、时间戳严格递增，三轴位置跨度约
  5.4 / 4.8 / 4.3 mm。该窗口日志四元数首尾夹角约 0.81°，
  说明位置小幅波动不等于姿态漂移已消除，仍需标定和后续验证。
- 尚未完成 IMU 六姿态、相机—IMU 联合标定和动态轨迹精度验证。
  本次静止测试不能证明动态精度或保证长期不漂移。
- RViz 累积的仍为稀疏路标；本修改不包含深度稠密重建。
