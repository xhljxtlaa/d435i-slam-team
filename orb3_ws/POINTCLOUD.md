# ORB-SLAM3 点云地图

当前按用户要求只使用 ORB 原生特征地图点，默认 `dense_mapping=false`。
深度表面点云的投影、缓存和融合已停用，RViz 显示 `ORB Feature Map`。
D435i 深度数据仍参与 RGB-D 定位。以下保留可选表面模式的实现说明。

## 显示与话题

- `/orb3/map_points`：ORB 当前地图中的优化后稀疏路标，默认显示为蓝色点。
- `/orb3/map_cloud`：可选深度表面地图，当前为空。
- `/orb3/depth_points`：可选单帧深度点，当前为空。

全部是 `sensor_msgs/PointCloud2`，坐标系 `orb3_map`，字段 x/y/z/intensity。
XYZ 单位为米；表面模式的 intensity 为红外灰度，原生特征路标使用固定值 255。
默认约 1 Hz 发布，Reliable + Transient Local；重开 RViz 可以接收已有地图。

## 当前稀疏度设置

可选表面模式保留以下设置；当前特征点模式不使用深度采样和体素参数：

- 体素尺寸 0.05 m，亦即约 5 cm 一格。
- 深度像素采样步长 8。
- 最大地图点数 100000。
- 深度范围 0.18–6 m，剔除孔洞和明显深度边缘。

如需显式恢复可选表面模式，可在启动时覆盖参数，例如：

```bash
/home/he/orb3_ws/start.sh rgbd -p dense_mapping:=true -p map_voxel_size:=0.08
```

上例使用 8 cm 体素。直接使用 `ros2 run` 时默认同样停用表面建图。

## 拼接与坐标维护

特征模式直接发布 ORB 当前地图的世界坐标路标，随 SLAM 优化更新。
以下深度投影和融合步骤仅在可选表面模式启用时执行：

输入深度与用于定位的图像来自同一帧配对，使用本机已验证的左目内参及
残余畸变计算相机光线。不会把已经是世界坐标的 ORB 路标重复变换。

按时间戳匹配 ORB 关键帧，保存关键帧相机坐标中的深度点；每次发布地图，
使用最新关键帧位姿重新做体素融合。被剔除关键帧通过父关键帧关系更新位姿。
因此可随关键帧优化更新地图，而不是永久累积旧世界坐标。

只保留最多 200 个深度关键帧和 120 帧待匹配数据，保证内存有界；超过
容量会淘汰最早的深度关键帧。轨迹完全丢失、地图重置或活动地图 ID 改变时，
保存旧地图并清空当前点云，避免拼接不同坐标系。惯性世界对齐可以通过更新
关键帧位姿重新投影点云；这不代表惯性标定已完成。

默认每个体素允许单个关键帧贡献，便于静止时立即看到地图。可以通过
`-p map_min_observations:=3` 要求三个不同关键帧确认，但静止且只有一个
关键帧时不会产生融合表面。该确认计数不是同一帧内重复像素计数。

## 保存和管理

正常退出时自动保存最近一次地图快照到该次运行目录。需要立即保存时：

```bash
source /opt/ros/humble/setup.bash
ros2 service call /d435i_orb3/save_map std_srvs/srv/Trigger '{}'
ros2 service call /d435i_orb3/map_stats std_srvs/srv/Trigger '{}'
```

`save_map` 返回实际输出路径：当前 `map.ply` 和 `map_sparse.ply` 均保存
ORB 特征路标；只有启用可选表面模式时 `map.ply` 才保存表面点云。
`map.json` 记录地图类型、坐标系、点数和关键帧数。
使用 binary little-endian PLY，保留灰度 intensity 属性。

仅在可选表面模式中清空融合缓存：

```bash
ros2 service call /d435i_orb3/clear_map std_srvs/srv/Trigger '{}'
```

请求在下一帧处理时生效，原快照先保存为 `map_epoch_N.ply`；不会重置
定位器。清空后需要新的关键帧来重建表面，静止时可先查看 `/orb3/depth_points`。
特征模式的地图由 SLAM 管理，清空服务返回说明；重启定位节点可重新建图。
